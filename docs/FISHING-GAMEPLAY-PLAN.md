# Tidewater 钓鱼真实性与可玩性改造计划

状态：设计草案，尚未实现。日期：2026-10-14。

本计划以当前工作区源码为基础，优先使用已有 18 种鱼和现有海岛。新增鱼种、鲨鱼模型与动画放到后续阶段。文中的时间、概率、数量、经济和物理参数都是首轮调参建议，不是现实鱼类的生物学测量值，也不是《俄罗斯钓鱼4》的内部参数。

## 1. 产品目标与范围

### 1.1 希望玩家反复回来做什么

让玩家因为“知道得更多、操作得更好、发现了值得再试的目标”而想继续钓鱼。主要吸引力来自四件事：

1. **找鱼有发现感**：看见鱼群、追逐、跃水或探鱼器回波，判断这一带有什么、鱼在哪个水层。
2. **下竿有选择**：同一个钓点，饵、深度、时段和呈现方式不同，结果不同；几分钟没有咬口也有合理原因。
3. **遛鱼有掌控感**：鱼的方向、冲刺和体力会改变局面，玩家能靠泄力、竿角、收线时机和走位扳回局势。
4. **成功有故事**：一次长时间较量、一个个人纪录、一个自己发现的钓点，值得记住；装备进步让玩家能挑战新的目标。

三项重点的关系：真实性提供可信的因果，可玩性让因果可观察、可操作，上瘾性来自理解和掌握这些因果后的成就感。

### 1.2 首轮必须解决的问题

- 按住左键不再保证持续缩短鱼的距离；鱼冲刺时可能停滞，甚至继续带线。
- 大鱼不能仅凭“离玩家足够近”就自动入袋。
- 鱼体力不再只随时间下降；压力不足时可以缓和或恢复。
- 咬钩由当前水域中的鱼、鱼的活跃状态和钓法共同决定，允许连续几分钟没口。
- 可见的可钓鱼与实际可钓资源产生联系，之后“看到鲨鱼，判断附近能钓鲨鱼”才有意义。
- 长局投入能可靠保存；退出、刷新、服务故障不会轻易吞掉几十分钟的较量。

### 1.3 暂缓范围

新增大量鱼种、完整鲨鱼资产、繁殖食物链模拟、多竿并钓、多人联网、全套真实钓具目录、复杂维修工坊，均不作为首轮前置条件。先让已有鱼钓起来有区别，再扩展内容。

已有的鲸、海龟、鳐等环境生物不因这次改造自动变成可钓目标。

## 2. 当前实现核查

| 功能 | 当前实际行为 | 对玩法的影响 |
|---|---|---|
| 水域判定 | 按浮漂落点的世界坐标、水深、距礁区和码头的距离，计算浅滩、礁区、码头、海湾、深水权重；水域可以重叠 | 已有空间基础，可以继续扩展，不必先重做地图 |
| 咬钩等待 | `Bites.biteDelay()` 依据水域和昼夜生成较短的随机等待，弱水域权重还会被抬高；重新抛竿重新生成等待 | 大多数落点很快有口，等待缺乏目标选择和资源变化 |
| 鱼种与体型 | 按水域、稀有度、时段加权抽鱼种；重量随机且偏向小鱼，长度由种类和重量计算 | 体型不是固定值，但与水里看到的个体没有联系 |
| 扬竿 | 浮漂先试探，再进入短暂吃口窗口；点击后进入遛鱼 | 已有雏形，但行为变化和误判空间较少 |
| 收线 | 按住收线始终让距离减少；猛冲只降低减少速度 | 核心策略容易退化成一直按住左键 |
| 鱼体力 | 每次更新都下降，绿色张力区下降更快 | 即使施压不足，也能等鱼疲劳 |
| 成功条件 | `distance < 1.2` 即判定钓到，不检查此时是否仍在猛烈挣扎 | 靠近就成功，少了最后控鱼与起鱼过程 |
| 水中游鱼 | `FishSchools` 自己模拟游动、捕食和跃水，与咬钩抽样分开；远处鱼群会停用部分模拟 | 看见鱼只能看风景，不能可靠判断这条鱼或这群鱼能否钓到 |
| 探鱼器 | 根据地形、水域权重估算“鱼量”，不是读取真实鱼群 | 买探鱼器后获得的是地形提示，尚非鱼群信息 |
| 装备 | 鱼线主要提升 `lineKg`，卷线器提升速度，竿主要提升抛距；鱼线的 lb 标称与 `lineKg` 数值不一致 | 装备接近线性数值升级，受力单位不能直接视为真实数据 |
| 时间 | 昼夜速度默认约 8 分钟一个游戏日；T 暂停昼夜，等待、波浪和遛鱼继续 | 屏幕上的时钟不能用来衡量真实遛鱼耗时 |
| 存档 | 项目 `data/game-save.json` 共用存档，已有校验、修订号冲突处理和原子写入；主要保存钱、鱼获、图鉴、升级等 | 有持久化基础，但没有完整的在途大鱼与水域状态恢复 |
| 船上钓鱼 | 船仍可能翻覆；目前过度倾斜或相机入水会禁止/取消钓鱼 | 已挡住异常钓鱼，翻船后的玩家恢复仍需单独设计 |

核查涉及：`src/game/Game.js`、`Bites.js`、`CatchMinigame.js`、`FishingRod.js`、`FishTable.js`、`Gear.js`、`GameHUD.js`、`Minimap.js`、`GameState.js`、`ProjectStorage.js`、`SaveFormat.js`、`src/world/Fish.js`、`src/world/Reef.js`、`src/player/Player.js`，以及现有钓鱼、起鱼和项目存档测试。

目前隐藏 B 键大鱼测试会让后续咬钩选中 35 kg 大海鲢，不自动增强装备，也不在游戏内显示快捷键提示。它仍沿用普通鱼获结算。后续应把测试场景与正式经济、纪录隔离，不能把“已隔离”当成当前事实。

本计划的水域消耗、鱼群共享状态、数值档位和保存方案是针对 Tidewater 的设计提案。没有官方依据的玩家传闻，例如某种精确“窝点冷却公式”，不作为 RF4 已实现的事实。

## 4. 遛鱼的现实基础与游戏取舍

### 4.1 是否要朝鱼游动的反方向收线

收线主要沿鱼线发生；玩家更能控制的是**竿的方向、竿与线的夹角、泄力和自身位置**。用适当侧向压力改变鱼的方向，比把“始终反向拉”做成固定奖励更合适。

侧压可以迫使鱼改变姿态、争取位置，但不是对所有海鱼和钓具都通用的一条角度规则。Troutbitten 对侧压的说明来自流水中的鳟鱼经验；本项目借鉴“方向控制有价值”这一原则，海钓具体效果仍需按鱼的行为和钓具调试。[侧压原始讲解](https://troutbitten.com/2026/08/23/podcast-fighting-big-fish-5-side-pressure-s20-ep5-video-and-audio/)

### 4.2 是否时而送、时而紧来耗体力

可以有这种节奏，但“送”更接近**保持压力，让泄力受控地出线**，而不是主动把线完全放松。鱼猛冲时由泄力保护线和钩；冲刺减弱后回收失地。适当竿角提供缓冲。小鱼配合足够强的装备可以平稳收回，大鱼则更需要管理压力。[Shimano 遛鱼说明](https://fish.shimano.com/en-AU/content/c/Articles/how-to/playing-fish.html)

针对纺车轮，厂家手册明确提醒避免顶着出线泄力继续收线；鱼停下冲刺后，再利用竿和卷线器收回线。这支持改掉目前“按住总能拉近”的行为。[Offshore Angler 纺车轮手册](https://assets.basspro.com/image/upload/v1677530153/PDFs/productmanual/productmanual_OffshoreAngler_FrigateSpinningReel_FG3000_FG4000.pdf)

### 4.3 游戏中的操作原则

- 冲刺时：观察带线速度，减少硬收，必要时降低泄力，保留可控张力。
- 缓和时：收回线，利用合适竿角施压，避免留下过多松线。
- 横向逃跑时：调整竿向和站位，尝试把鱼引离障碍、拉向可起鱼区域。
- 临近时：防止最后一次冲刺，准备起鱼；不因距离短而自动成功。
- 小鱼和明显匹配的重装备组合应保持轻松，不把每条鱼都做成高强度挑战。

泵竿可作为一项技术：适度抬竿获得控制，再降低竿位并收掉余线。先针对当前钓具验证，不让所有未来钓法都强制重复同一套动作。

## 5. 功能 A：水域资源与可见鱼群

优先级 P1；最小版本应与核心玩法一起验证。目标是让玩家通过观察获得有效线索。

### 5.1 同一套水域状态服务可见鱼、咬钩和探鱼器

建立逻辑上的鱼群/鱼资源状态，至少记录：所在区域与水层、已有鱼种、体型分布、活跃度、警戒度、移动趋势和可钓资格。

三种输出读取同一状态：

1. 世界表现：抽取一部分个体显示游动、追逐或跃水。
2. 钓鱼机会：从附近、能接触当前钓组的资源中产生接近和吃口。
3. 探鱼器：读取探测范围内的资源，生成有误差的回波。

不能分别随机生成三个互不相干的结果。渲染数量也不能直接等于鱼的总数：性能设置、视距和是否看向水面都不应改变咬钩机会。

### 5.2 哪些鱼需要显示

首版先选已有鱼中的两类：一类小型群游鱼，一类醒目的大型鱼。大海鲢、鲹类可作为候选，最终按现有游鱼与鱼获模型的复用成本选型。

近处显示少量代表个体；远处用水面扰动、跃水或群体轮廓提供线索。深水鱼通常不可直接看见，可通过地形和探鱼器判断。无需把全部鱼实例常驻渲染。

已经有的跃水动画应逐步与鱼群状态连接。接入前保留为环境表现，不能用它宣称那里一定存在某个可钓个体。

### 5.3 看到鱼到底意味着什么

| 玩家观察 | 应当成立的判断 | 仍然不保证的事情 |
|---|---|---|
| 看见一群已接入系统的可钓小鱼 | 观察时该片水域有这类鱼活动 | 投进去立即咬钩 |
| 看见可识别的大海鲢跃水 | 当时附近存在可钓的大海鲢资源，水层活动有线索 | 一定咬当前饵、一定是纪录体型 |
| 将来看到可钓鲨鱼巡游 | 鲨鱼功能已开放，该区域此刻存在可钓鲨鱼 | 立即咬口、轻装备能拿下、看到的个体永远留在原地 |
| 没看到鱼 | 目前没有得到目视证据 | 水下没有鱼 |
| 十分钟前看到过鱼 | 这里有近期活动记录 | 鱼群至今没有移动 |

同一个被显示的大个体可以直接成为上钩候选；若采用鱼群代表个体，也必须保证对应鱼种确实存在于同一片有效范围内。不能把可钓鲨鱼的视觉展示放在功能开放之前，仅靠“以后能钓”解释当前承诺。

### 5.4 坐标、范围与迁移

使用现有以米为单位的世界坐标：x/z 定位、y 表示高度或水深。水域是空间分布，不是只认几个固定命名点。

初版采用有范围的资源区域和连接路线，覆盖码头、礁缘、海湾与近海坡面。鱼群在区域内游动，部分随时段和水流沿路线移动。区域之间平滑过渡，不能玩家挪两米就完全刷新鱼。

导航上显示玩家需要的地名、深度和个人钓点标记。内部网格、资源编号和调试坐标不默认堆进主画面；可留给开发工具。

### 5.5 同一个位置为什么会没口

将三个原因分开：

- **资源减少**：鱼被带走，剩余可钓数量下降。
- **警戒升高**：反复抛投、脱钩、发动机靠近等使部分鱼更难接近。
- **活跃度变化**：时段、水层和迁移改变觅食意愿。

频繁钓获后，局部可能从热闹变冷清。不能每钓一条就把整片海强行清空，也不能所有区域最终永久枯竭。基础容量、邻区补充和休养恢复共同维持长期玩法。

首轮可尝试 30–60 米影响范围、15–40 分钟在线活动时间恢复警戒，均须调参。捕捞消耗与警戒恢复不同，不能仅等警戒消退就瞬间补齐所有大鱼。放生的个体保留短期警戒，不允许立刻重复钓同一条刷奖励。

### 5.6 接入探鱼器

探鱼器升级后显示水深、回波水层、强弱和群体趋势。回波受覆盖范围、移动、海况与设备精度影响，不直接报鱼名、精确重量和剩余数量。

首版把当前“地形适宜度即鱼量”改成“真实资源的粗略回波”。地形适宜度仍可作为找鱼依据，鱼群离开后则不应继续给出相同鱼量。

**验收**：看见可钓大鱼时，该片水域能查到对应资源；上钩、钓走、逃脱和迁移后，视觉与机会一致变化。调低画质、转身、远离再回来不会重新刷鱼；探鱼器不在空资源区域凭地形制造鱼群。

## 6. 功能 B：鱼饵、钓组与呈现策略

优先级 P1。目标是让等待有可调整的原因，并且不依赖增加鱼种。

### 6.1 第一版只增加少量有区别的选择

| 选择 | 主要作用 | 代价/局限 |
|---|---|---|
| 小型天然饵 | 针对已有中小型鱼，较容易获得反馈 | 容易被小鱼试探，难以筛选目标 |
| 鱼肉/较大天然饵 | 提高已有掠食性、大体型目标的适配度 | 等待更久，饵消耗更高，不保证每口都是大鱼 |
| 作钓水层 | 表层、中层、近底，先提供清晰的深度设置 | 深度不对可能有鱼也不吃；近底多挂底风险 |
| 静置/缓慢呈现 | 适配当前浮漂玩法，给漂移和适度调整以意义 | 不应通过高频点按统一提高概率 |

饵可先用简单图标和已有物品表现，不需要先补完整的新模型。适配关系依据当前鱼种整理，标记为游戏配置；在宣传为现实知识前另行查证鱼种资料。

大饵改变“愿意接近的鱼”和体型分布，不是强行把普通鱼的重量放大。饵的新鲜度、钩号、前导线和更细的钓组搭配可在后续加入。

### 6.2 钓法按阶段扩展

先完善目前的浮漂/天然饵流程，再考虑近底钓、路亚、垂直铁板和拖钓。每种钓法有自己的有效水层、饵运动和刺鱼方式。

不能仅换一个钓具名称，底层仍然全是浮漂下沉、点击、张力小游戏。也不能规定未来所有钩型和钓法都需要猛烈扬竿。

**验收**：同一有鱼水域，合适的饵与水层获得明显更好的接近率；不合适的组合允许长期没有有效咬口。玩家可以根据观察修正设置，且图鉴记录能验证这种变化。

## 7. 功能 C：找鱼、等待与咬钩

优先级 P0/P1。目标是允许空等，同时让改变策略有价值。

### 7.1 从固定短倒计时变成条件驱动的机会

咬口强度由以下条件共同决定：附近可接触的鱼量、觅食活跃度、鱼饵适配、水层适配、呈现质量、局部警戒，以及有限的环境修正。

首轮先做鱼量、饵、水层、时段、警戒。风、云、温度、潮流以后按能解释和验证的顺序加入，避免十几个不可见乘数使玩家只能查攻略。

可采用随时间变化的事件率模型：每段时间产生机会的概率为 `1 - exp(-λ × dt)`。`λ` 随场景变化，鱼不在附近或钓组无法接触目标时可以为零。随机性决定何时发生机会，条件决定机会是否值得等。

示例：在假定事件率恒定的简化情形下，每分钟 1 次机会，等 3 分钟仍无机会约为 5%；每分钟 0.25 次，等 3 分钟仍无机会约为 47%。这是数学示例，不是各鱼种的固定咬口数据。接近机会还可能止于试探，不能与最终上钩等同。

实现时可保存累计事件强度与一次抽样阈值，不必每帧重抽随机数。重抛、刷新、切浏览器和改画质都不能成为免费刷新稀有口的办法。

### 7.2 首轮等待节奏建议

以下是标准档连续作钓时的常见区间，单位为**现实经过时间**；它们不是保证下限、保底倒计时或最长上限。

| 情形 | 初始调参区间 | 玩家应获得的线索 |
|---|---|---|
| 活跃的小鱼群，饵和水层匹配 | 20–90 秒内常有试探或口 | 能观察到小鱼群或连续回波 |
| 普通钓点，条件大致匹配 | 约 1–3 分钟有一次机会 | 地形适宜，反馈不一定连续 |
| 鱼稀少、警戒高、时段一般 | 连续 2–8 分钟没口很正常 | 活动迹象较少，历史记录提示近期降温 |
| 用大饵专等稀有大鱼 | 5–15 分钟以上仍可能没有效口 | 有目标线索，玩家主动接受低频机会 |
| 当前没有适配资源，或水层完全错开 | 可以一直没口 | 通过观察、深度、探鱼器或换点排查 |

不设置“等满三分钟必咬”的常规机制。确需教玩家扬竿时，使用独立教学场景，明确告诉玩家这是练习；普通水域的规律保持一致。

### 7.3 等待中有什么可玩

玩家可以观察鱼跃、水面追逐、浮漂和风浪；核对水深和探鱼器；换水层、换饵、沿礁缘重新定位，或查个人钓点记录。

每次策略改变都需要一定呈现稳定时间。无效频繁重抛会打扰附近鱼、损耗饵或失去原先的接近过程，不能通过反复抛收批量抽口。新位置可以获得新机会，但挪一点点仍受同一区域资源与警戒约束。

### 7.4 咬钩有过程，不只有倒计时结束

建议流程：

`呈现稳定 → 鱼接近 → 试探/碰饵 → 吃口成立 → 刺鱼/建立负载 → 遛鱼`

接近可能没有反馈；试探可以是小幅抖动、横移或轻微拉动；有效吃口体现为更持续的位移或负载。风浪也会影响浮漂，但不能与有效口完全无法区分。

小鱼偷饵、目标放弃、玩家过早拉走饵、错过吃口，都可以成为结果。先做少量清楚的行为，再扩展差异。未知目标在起鱼前不必直接显示名字与精确重量。

**验收**：同地点连续作钓的长尾等待确实存在；换水层或换点能改善错误策略；连续重抛不能提高单位时间稀有鱼机会。30/60/120 FPS 的咬口分布一致，隐藏远处游鱼不会让当地资源消失。

## 8. 功能 D：刺鱼与上钩质量

优先级 P0。目标是增加咬口判断，又不变成反应速度小游戏。

### 8.1 判断比极短窗口重要

玩家先看漂或感受拉动，等明确吃口后建立负载。咬口窗口随鱼的行为、钓组与是否警戒变化；持续吃饵的口可宽一些，快速抢食的口短一些。初版不使用只有几帧的精确判定。

刺鱼考虑时机、当时松线和施力：早了可能把饵拉走；松线过多导致动作传不到钩；适度拉紧后刺鱼更可靠；连续猛烈抽竿会增加脱钩或过载风险。

### 8.2 上钩后不是统一质量

内部可有“牢固、一般、浅挂”等少量档位，用于后续钩的稳定性。质量受可解释操作影响，同时保留有限个体差异。不要玩家完美操作仍频繁无提示随机脱钩。

HUD 不必公布精确挂钩百分比。可以通过“钩未挂稳”等短提示或较明显的挣扎风险反馈，起鱼/失败后再给原因。

### 8.3 兼顾新手

入门鱼吃口较清楚，练习提示可以开关。成功刺鱼先给足够时间建立正常受力，不立刻用不可预判的大鱼冲刺秒断线。挑战来自后续管理，而非玩家还没理解就失败。

**验收**：乱点、过早提竿、明确吃口后稳妥提竿获得不同结果；熟练玩家成功率明显更高。重复刺鱼不能持续提升挂钩质量，也不会反复给鱼清空体力。

## 9. 功能 E：遛鱼、收线与体力较量

优先级 P0，是整项改造中最先验证的核心。

### 9.1 四个独立的量

| 量 | 表示什么 | 为什么要区分 |
|---|---|---|
| 鱼的位置与运动 | 世界中的位置、水层、方向和速度 | 横跑、向玩家游、下潜和船漂移不能只表现成一条距离数值 |
| 已放出的线 | 线杯实际放出长度，以及剩余容量 | 出线、收线、松线和直线距离不是同一个量 |
| 张力 | 钩、线、竿和泄力共同形成的受力 | 是否危险由受力与装备状态决定，不能只按鱼的公斤数判断 |
| 鱼的能量与爆发能力 | 长期耐力、短期冲刺储备和当前恢复状态 | 大鱼可以冲刺后缓和、缓和后再冲，而不是单条体力条线性掉到底 |

最低限度先使“收线量”与“鱼到玩家的距离”分开。正式方向控制必须有权威鱼位置，不能让钓竿视觉自己随机游动，再从另一个数值系统决定胜负。

### 9.2 收线要受到负载限制

左键代表玩家尝试转动卷线器，不再代表鱼必定向玩家移动。

- 负载较低：能按装备速度正常收回线。
- 负载接近有效收线能力：速度下降，摇柄和声音反映吃力。
- 超出能力：收线停滞；如果鱼的拉力超过泄力阈值，鱼仍能带线。
- 玩家继续硬收：首先损失效率并增加负载风险；磨损、热量作为后续细化。
- 鱼主动游向玩家：需要及时收掉余线，避免松线；不能把这种情况误判为鱼已经疲劳。

长线、深水、水流和玩家位置影响状态。不能从“收线按钮按下”直接扣减距离。

### 9.3 泄力是关键操作

增加可调泄力。它控制允许多大压力后线杯开始出线，与“收线开关”和“主动松线”分开。

较松：保护装备，冲刺时更容易出线，但难控制距离和障碍方向。

较紧：更容易施压和限制活动范围，但更接近断线、钩不稳与装备负载上限。

初版使用平滑、分档的泄力调节，避免零延迟开关式调节成为万能技巧。入门装备给出保守的默认设定，具体设定按系统模型与测试校准，不把一个百分比当成适用于所有钓具的现实定律。

### 9.4 竿角与侧压

鼠标控制视线的同时，需要一种能稳定控制竿向的方式，见第 10 节操作方案。

合适侧向压力能改变鱼的运动方向，帮助把鱼引离码头桩、礁石或船底。作用大小取决于线的方向、当前负载、鱼的转向能力和玩家位置。

竿直接指向鱼时缓冲不足；过度高举、剧烈抽动增加瞬时危险。竿的抬起和放低要平滑，不能靠疯狂甩鼠标获得免费伤害。

不在界面长期画一个“必须朝反方向”的完美箭头。可给新手短提示，正式玩法让玩家从线向、竿弯和鱼的运动读出状态。

### 9.5 鱼的行为与体力

先制作四个可复用行为原型，给已有鱼配置不同权重和参数：

| 原型 | 行为重点 | 玩家的应对 |
|---|---|---|
| 小型群游鱼 | 短冲、较弱转向、容易靠近 | 保持合理受力，及时收线 |
| 近岸快速掠食鱼 | 横跑、突然转向、连续短冲 | 调整竿向，防止松线或擦桩 |
| 大型跃水鱼 | 强冲、转向、跃水后负载变化 | 留有线量，控制瞬时压力，不在跃水时猛抽 |
| 深层/近底鱼 | 下潜、持续抗拉、尝试靠近结构 | 控制水层和竿向，争取把鱼引离障碍 |

原型是初版玩法抽象，不是对所有已有鱼种的生物学分类；鱼种映射单独整理。

体力变化原则：

- 高强度游动、对抗有效压力和持续转向消耗能量。
- 很低的压力下，鱼可以恢复短期爆发储备；长时间完全松手不会免费赢。
- 压力合理且持续，玩家能逐步获得优势；压力过高则首先损害钓组可靠性。
- 疲劳降低冲刺强度、持续时间和转向恢复，但鱼仍可能最后挣扎。
- 行为有局势依据与个体随机差异，不固定为每三秒冲刺一次。

初版用“长期能量 + 短期爆发储备”两个状态即可，不必模拟完整代谢。降低耐力或速度必须连续，不能体力到零后瞬间变成静止物体。

### 9.6 一条大鱼的典型过程

1. 刺鱼后建立受力，鱼进入第一轮冲刺，玩家先保住线和钩。
2. 第一轮冲刺结束，鱼在远处改变方向；玩家用侧压和合适收线争取距离。
3. 鱼恢复一些爆发力，再次带线；玩家调整泄力，判断要不要沿岸跟随。
4. 鱼逐渐疲劳，收线窗口变长，但可能下潜或尝试绕结构。
5. 鱼接近岸/船，玩家保持控制，完成起鱼；仍有小概率出现可观察的最后一冲。

这些是可能出现的局面，不是强制五段脚本。熟练操作与匹配装备可以缩短过程，不能让鱼到某个距离就锁住，强行等满规定时间。

### 9.7 第一版与后续风险机制

第一版保留断线、脱钩、放尽线量三种主要失败，加入负载、竿角和钩稳定性。礁石/码头磨线用少量已知结构验证后再铺开。

泄力发热、装备耐久、钩变形、玩家耐力和复杂绕障放到后续。一次失败先损失鱼获、饵和有限耗材，完整竿轮报废需等经济闭环稳定后再考虑。

失败必须有原因反馈，例如“高负载持续过久”“鱼游向你时松线”“鱼线擦过码头桩”“线杯余量用尽”。不要直接弹出无法诊断的“运气不好”。

### 9.8 起鱼是独立阶段

进入起鱼范围后，同时检查位置、水深/岸沿、鱼是否仍在强冲、当前张力与起鱼工具容量。

小鱼可有简洁的自动辅助起鱼；大鱼需要把鱼引入可控范围，再用抄网或船边起鱼操作。首版允许用已有动作配合明确交互完成，抄网模型和丰富动画后补。

抄网操作不采用突然出现的 0.2 秒按钮提示。无法起鱼时应能继续控鱼和换位置，而非因没有新模型卡死。

鱼成功落入可控起鱼状态后才进入鱼获结算。鱼的体力不必为零，但“离得近、仍高速逃窜”不能直接成功。

**验收**：匹配装备的小鱼仍可轻松收回；大海鲢等强鱼用持续硬收不能稳定获胜；完全松手会丢失优势，合理控鱼能明显改善成功率和耗时。临近但仍冲刺的鱼不能自动入袋，长局不会靠固定倒计时结束。

## 10. 功能 F：输入、反馈与画面信息

优先级 P0，随核心遛鱼同步制作。

### 10.1 第一版操作候选

| 操作 | 作用 | 设计约束 |
|---|---|---|
| 左键 | 刺鱼；遛鱼时尝试收线 | 支持“按住”和可选“点击切换收线”，减轻长局手指负担；自动收线不自动调整泄力 |
| 松开左键 | 停止主动收线 | 鱼仍通过已设泄力保持受控负载，不等于完全松线 |
| 滚轮 | 作钓时调深度；遛鱼时调泄力 | 由当前玩法状态独占，不能同时调船视角或其他界面 |
| 右键按住 + 鼠标 | 遛鱼时调整竿的侧向/抬降姿态 | 钓鱼状态接管；空线时保留收回逻辑；镜头可有限跟随，不能突然甩视角 |
| WASD | 沿岸或在甲板上调整位置 | 真实改变竿尖位置，不能只播放走路动画 |
| E | 起鱼，条件满足时出现交互 | 不与船交互、交易和收起鱼获同时触发 |

这是待试玩的映射方案，不是现有操作说明。先制作能实际测试的输入原型，比较“镜头带动竿向”和“右键独立控竿”哪种更舒服。允许玩家改键；不增加大量必须同时按住的组合。

隐藏大鱼测试键继续不出现在教程、键位提示和普通 HUD 中。

### 10.2 主要反馈应来自世界

鱼线方向与速度、竿的弯曲、线杯出线声、卷线器吃力声、鱼的水面运动，应该对应同一遛鱼状态。声音能帮助判断，但静音玩家仍能靠视觉获知关键风险。

镜头摇晃保持克制，可降低强度；不能靠剧烈晃动制造“困难”。大鱼不一直显示精确名字、体重与血条，避免世界感变成刷怪。

### 10.3 简洁 HUD

初版显示张力、当前泄力档、剩余线量、距离/水层的必要信息。鱼的体力可先保留方便调试，正式显示可切成“活跃、缓和、疲惫”等粗略状态；详细百分比作为辅助选项。

风险提示只在必要时出现，比如余线不足、持续过载和起鱼条件不满足。不要长期堆五六条教学文字。反馈颜色之外还需有形状或文字区别。

起鱼后保留现有鱼获卡，增加本次遛鱼耗时、最大出线和关键过程的简短回顾。失败后给一个主要原因和一个可改进操作，不连弹多层提示。

**验收**：不看调试数值也能从声音、线向和竿弯区分冲刺/收线停滞/松线；滚轮不会同时触发多个系统；点击切换收线与按住模式不会改变受力规则或成功率。

## 11. 功能 G：游戏节奏与长时间较量

标准档先上线；长局真实档必须在第 12 节的暂停、保存与恢复通过后开放。

### 11.1 分开等待难度和遛鱼难度

“更真实”不能仅靠降低咬口频率。等待考验信息与选择，遛鱼考验判断与操作，两者分别调参。

同样不能把所有鱼的耐力统一乘十。长局需要更多局势变化、更长的爆发储备和追鱼空间，而不是重复几百次同样的松手/按住循环。

### 11.2 时间档位草案

单位均为现实经过时间。表中是适配装备、有效操作的典型目标区间，不是固定时长或成功保证。大小分类按鱼种与装备的相对挑战确定，不用一个重量阈值覆盖所有鱼。

| 档位 | 小鱼遛鱼 | 有挑战的中型鱼 | 大型目标鱼 | 定位 |
|---|---|---|---|---|
| 标准海钓，推荐默认 | 约 30 秒–2 分钟 | 约 3–8 分钟 | 约 8–20 分钟 | 一次普通游玩能完成多种活动，同时大鱼有足够分量 |
| 长局真实档，后续开放 | 约 1–5 分钟 | 约 8–20 分钟 | 约 20–60 分钟，极端局面可更久 | 玩家主动投入较长时间，必须能暂停、退出后继续 |
| 短局辅助档，需求确认后再做 | 约 15–45 秒 | 约 1–3 分钟 | 约 3–8 分钟 | 保留操作关系，缩短体验；独立标记纪录档位 |

小时级较量保留为罕见的大鱼、装备偏弱或局势不利的结果，不把每条大鱼强制锁到一小时。增加难度后应重新校准售价与成长速度，否则原先十几秒一条的经济会崩。

标准档等待参考第 7 节；长局档可延长普通和稀有机会的间隔，但热闹小鱼区仍要有反馈。不能简单让所有区域一起变死海。

### 11.3 长局的决策密度

局面改变由鱼的行为与能量驱动。首轮观察目标：活跃阶段约每 10–30 秒出现值得判断的变化，缓和阶段给玩家检查线量、调整竿向和喘息的空间。

该目标用于评价“是否一直在重复”，不是给鱼写固定事件计时器。好的长局应有守住第一冲、夺回一半线、成功转向、引离礁石等可记住的进展。

### 11.4 时间系统要拆清楚

| 时间 | 用途 | 暂停与存档要求 |
|---|---|---|
| 玩法模拟时间 | 遛鱼、等待、局部警戒等运行 | 完整暂停时停止；低帧率不能改变难度 |
| 游戏昼夜时间 | 光照、当前时段、相应活跃模式 | 保留 T 键暂停昼夜；不把它当作完整暂停 |
| 现实经过时间 | 长局耗时记录、存档时间戳 | 明确区分实际作钓时间和暂停时间 |

潮流先用独立、缓慢的玩法相位，再与可见海况逐步连接。现有 8 分钟一日的光照不能意味着每几分钟整个水域清空再补满。

T 键冻结昼夜后，鱼仍可因捕捞和警戒变冷清；不能通过固定黄昏获得无限刷新。手动切时段也不能重置人口与接近过程。档位在一次遭遇开始时固定，不能临近起鱼临时切到短局刷真实档纪录。

**验收**：同重量鱼因装备、操作与个体行为产生不同耗时；大鱼有得失和阶段进展；暂停时间不消耗鱼体力、不算主动遛鱼耗时；玩家不必连续按住鼠标几十分钟。

## 12. 功能 H：长局暂停、保存与恢复

优先级 P0，作为长局发布门槛。存档继续放在当前项目，不回退到浏览器独立存储。

### 12.1 明确暂停入口

当前 Esc 是释放鼠标，T 是暂停昼夜。新增“完整暂停”功能，菜单有清楚入口与可配置热键，和这两个行为区分。

建议在遛鱼时释放鼠标后进入暂停控件；是否直接自动暂停作为选项，用试玩确认，不能只释放鼠标却仍让鱼无反馈地跑线。切走标签页、失去焦点或浏览器长时间挂起时，单人游戏默认完整暂停。

暂停冻结鱼、线、负载、等待、警戒计时及相关世界交互；不能只冻住视觉，底层照样断线。恢复前清理鼠标/键盘按住状态，避免玩家回来后自动猛收。

### 12.2 保存哪些状态

除现有钱、鱼获和升级，新增必要数据：

- 水域资源的变化、警戒、近期迁移与受限恢复时间戳。
- 当前钓组、饵、水层、已消耗耗材与作钓档位。
- 当前遭遇的唯一编号、鱼的身份/体型、行为、位置、能量、随机状态。
- 放线长度、竿轮与钩状态、泄力、已有负载风险和主动遛鱼时间。
- 玩家与船的必要位置、起鱼阶段、已结算标记。

只保存恢复所需的逻辑状态，不保存 GPU 缓冲、动画逐帧数据、鼠标动作或整个渲染世界。方案初期可限制为一条活动钓线。

### 12.3 检查点与故障处理

先尝试每 15–30 秒保存一次活动检查点，并在正式上钩、明显阶段变化、暂停、退出和结算时提交。写入串行合并，避免每帧写文件。

恢复默认进入暂停状态，玩家确认继续后再运行。加载不重抽鱼、不恢复满体力、不清空过载和磨线风险，也不重复刺鱼输入。异常关闭最多回到最后成功检查点；界面显示最近成功保存时间。

鱼获结算使用遭遇唯一编号，保证鱼舱、钱、纪录和水域资源变更一起提交。重复恢复、重试请求、重复点击收起鱼获都不能发两次奖励。起鱼已经完成但提交失败时保留待结算状态，不让玩家白打一次。

服务暂时不可用时保留可重试的待保存状态和提示。不能只依赖关标签页时的最后请求；当前退出保活请求有体积约束，新增水域状态后尤需通过周期检查点保障。

### 12.4 多浏览器与离线时间

共用存档不等于可以同时玩两份独立世界。当前修订号只能挡住冲突覆盖，不能阻止两边都消耗同一条逻辑鱼。

长局版本建议增加一个活动会话所有权机制：只有一个页面可推进共享游戏，其他页面先只读或明确接管；旧页面失去所有权后停止推进，不靠覆盖存档合并两条在途鱼。切浏览器通过保存和接管继续同一份进度。

服务故障时允许原页面保留内存中的待保存局面；其他页面不能在所有权未知时自动另开同一局。保存冲突先暂停并保留恢复材料，再让玩家加载当前共享存档或接管，不能悄悄覆盖。

离线水域恢复单独计算：按时间戳一次性应用有限补充，初版可设数小时的恢复上限，具体调参。暂停、反复刷新和重复加载不能反复领取恢复量；活动大鱼离线期间保持冻结。单人本地存档无法完全防系统时钟修改，先保证正常使用可预测，不引入重型反作弊。

### 12.5 格式演进

当前存档是严格的版本 1 格式，只接收既定键。新增字段需要同时更新 `GameState`、`SaveFormat`、`ProjectStorage` 和服务校验，并设计显式版本升级；不能直接塞新键然后期望服务接受。

保留现有项目鱼获、图鉴、钱与装备；新水域字段用合理默认值初始化。“不用管旧存档”是此前浏览器旧存档迁移的范围，不应据此清掉现在已经保存在项目中的进度。

检查点限制大小和数量，不让整个海域的所有渲染鱼逐条进入目前约 1 MiB 的存档。开发测试用独立场景或副本，避免隐藏大鱼测试修改正式经济。

**验收**：遛鱼中刷新、关闭后重开、切浏览器接管、服务中断再重试均能恢复最近保存局面；两页不能同时推进；恢复不会重复奖励或重抽大鱼；断线/失败终态也正确保存。

## 13. 功能 I：装备成长、经济与长期目标

优先级 P1/P2。目标是让钓小鱼、探新点和挑战大鱼都值得做。

### 13.1 装备应改变选择

| 装备维度 | 获得的能力 | 保留的权衡 |
|---|---|---|
| 线强度、直径、伸长与耐磨 | 更大压力余量、不同缓冲与绕障容错 | 线杯容量、呈现特征、敏感度等权衡，逐项验证后加入 |
| 轮的有效收线负载、泄力与线容量 | 有负载时仍能收线，更稳的出线与追鱼余量 | 重量、速度、价格与后续磨损 |
| 竿的承载、调性与长度 | 缓冲、方向控制、不同钓组适用性 | 长竿并非任何情况下都更好 |
| 起鱼工具 | 能稳定处理更大个体 | 起鱼位置与容量限制 |
| 探鱼器和船 | 找到更好的水层、到达更远区域 | 燃油、海况、定位与漂流管理 |

内部受力统一用牛顿，长度用米，时间用秒；展示可转换为 kgf/lbf。鱼质量 kg 与鱼线承载力不能混用。当前 lb 标签和 `lineKg` 的对应关系要先校准，再制定新装备价格。

第一版不要求配置几十件装备，可先把现有升级档补上合理承载、泄力和容量。装备够强时小鱼简单是正常结果；大鱼难度来自相对负载和行为，而非给高级装备强行削弱。

### 13.2 成长节奏

小鱼提供相对稳定的入门收入和操作练习，中型鱼提高收益与风险，大鱼承担纪录和高回报目标。新手区域应长期可用，但也遵循资源与行为规则，不必每竿必有口。

首次有效升级可暂以约 20–40 分钟正常游玩为观察目标；这不是最终经济承诺。按等待、成功率、航行、失败耗材和交易时间统计净收益，而非只按一条鱼卖价调数值。

不要求玩家必须先连续钓到大鱼才能买基础修补和燃油。保留低风险岸钓和最低限度可用装备，使失败后仍有恢复路线。

### 13.3 比增加鱼种更便宜的长期目标

- 个人重量、长度、最大出线、标准/真实档纪录。
- 第一次在新区域找到某种已有鱼，补全该鱼的习性观察。
- 同一种鱼用不同钓法或水层钓获，验证自己的判断。
- 某个高质量目标的准备与挑战：先找点，再配装备，最后尝试。
- 可重复的小型委托，如交付某类已有鱼、调查一片水层；不要求每天上线才能保留进度。

纪录与任务不能鼓励无成本重复放生重钓同一条鱼。核心回报仍是鱼获与自己的发现，任务只是给方向，不占据全部玩法。

### 13.4 个人钓鱼日志

扩展现有图鉴和纪录，保存鱼种、体型、地点、时段、饵、水层、作钓档位、耗时和成功/主要失败原因。记录“某时看到鱼”“某处钓到过鱼”，不要把过去记录伪装成实时保证。

地图支持个人标记和近期活动摘要，能回顾哪种策略有效。发现未知目标时保留“未确认的大型活动”，起鱼后再补全种类。

### 13.5 磨损后加，先确保经济可承受

磨损基于高负载、擦障和使用强度，先显示状态变化和检修需求，再逐步加入轻量成本。一次常规较量不能突然毁掉全套装备。

可参考 RF4 的装备匹配与维护关系，但本项目不必照搬每个部件、油脂、维修等待和商店目录。先让维修成为“准备下一次挑战”的选择。

**验收**：不同装备搭配有可感知优势和局限；高级装备缩短合适目标的较量但不创造不存在的鱼；失败后的净经济仍允许继续游玩；日志能帮助玩家改善下一次选择。

## 14. 功能 J：海况、潮流与船上作钓

优先级 P2。已有画面海况应逐步产生清楚的玩法影响。

先实现水流对饵漂移、线弧和鱼运动的影响，再增加局部潮流阶段与水层变化。风浪主要改变观察难度、船稳定和钓组呈现；不要无说明地给全鱼种乘同一个“下雨增鱼率”。

环境关系少而明确，写入图鉴或观察日志，例如“这类鱼今天在坡面上层活动更多”。每一条关联在游戏里可验证；真实习性另按鱼种查证。

船上钓鱼先保持安全状态约束，再改善站位、漂流与翻覆恢复。长局保存必须能恢复可靠甲板位置，不能从存档加载到海底。

后续追鱼允许玩家或简化助手低速调整船位，同时维持钓竿受控；不能要求单人同时完整驾驶和精确遛鱼。发动机追鱼可能减少线量压力，也会制造噪声与钓组位置风险。

翻船后应进入明确的落水/脱离与恢复流程。若选择让船不易翻，则需要稳定性调参和极端海况测试；它不与本次“先完善钓鱼核心”捆绑为首版物理重做。

**验收**：漂流会真实改变饵与线，位置变化不会刷新同一区域资源；危险船姿不能继续起鱼结算；长局不因异常船姿把玩家永久困住。

## 15. 功能 K：后续鲨鱼与新鱼类

优先级 P3，本轮不制作资产。前面统一资源、可见鱼与遛鱼模型，是加入鲨鱼的基础。

新增一个鱼种需要鱼获和游动资产、种类数据、体型/长度关系、出现区域、水层、饵适配、行为原型、钓组要求、起鱼规则、价值/纪录与测试场景。鲨鱼还需评估体型、船边表现和起鱼方式，不能简单套用小鱼悬挂动画。

目标体验：玩家看到鲨鱼在区域内活动，能记住位置、判断水层、准备合适钓组并等待机会。鲨鱼离开则信息逐渐失效；咬钩来自相同逻辑资源，不是看到以后偷偷提高全图抽中鲨鱼的概率。

先用现有大型鱼完整验证这套体验，再投入鲨鱼模型和动画。首版也不加入鲨鱼抢走已上钩鱼之类会显著改变风险与动画成本的机制。

**验收**：仅靠新增鱼种配置和资产即可接入既有流程；可见性、可钓资格、钓组条件和资源消耗一致，不需要为每个新鱼种再写一套钓鱼系统。

## 16. 实现边界与性能方案

本节记录实现方向，具体类名和拆分在开发前再按源码确定。

### 16.1 唯一玩法事实源

`Game` 继续协调玩家、作钓和世界。水域资源、钓鱼遭遇和受力模型各有单一状态所有者；钓竿、游鱼渲染、HUD 和探鱼器读取状态，不各自随机决定胜负或鱼量。

建议演进关系：

`水域资源 → 饵接近/咬口 → 活动遭遇 → 受力与鱼行为 → 起鱼 → 一次性结算`

`游鱼表现 / 探鱼器 / 日志 ← 读取相应玩法状态`

保留 `CatchMinigame` 的协调位置或逐步替换其内部，不一边保留旧的距离获胜逻辑，一边另加一套新物理胜负。`FishingRod` 原有竿弯、鱼线和鱼位置表现必须改成消费权威状态。

### 16.2 现有模块改造方向

| 位置 | 计划职责/改动 |
|---|---|
| `Game.js`、`Bites.js` | 从短倒计时和纯加权抽样，接入资源、钓组与分阶段咬口；统一遭遇与结算 |
| `CatchMinigame.js` | 受负载限制的收/放线、鱼运动、能量与行为、失败和起鱼条件 |
| `FishingRod.js` | 竿角输入，鱼线与竿弯消费玩法状态；停止独立决定鱼的位置 |
| `FishTable.js`、`Gear.js` | 补充现有鱼的行为与饵适配、统一受力单位和装备边界 |
| `src/world/Fish.js`、`Reef.js` | 逻辑资源驱动代表鱼表现，保留现有动画、批处理和视距优化 |
| `GameHUD.js`、`Minimap.js`、图鉴相关 UI | 少量关键反馈、真实回波、个人钓点与历史策略 |
| 输入与 `Player.js` | 作钓状态的输入独占、竿尖位置、走位/船姿、暂停时的输入清理 |
| `GameState.js`、`SaveFormat.js`、`ProjectStorage.js`、`tools/project-save.mjs` | 新版本状态、检查点、结算幂等、共享会话所有权 |

第三方模型、引擎生成数据和大量渲染 shader 不是首轮主要修改范围。

### 16.3 模拟预算

遛鱼用固定或稳定的物理时间步，处理积累时间时限制最大步数。标签页挂起后进入暂停/恢复，不用一个巨大 `dt` 把几分钟的出线和断线瞬间算完。

水域资源低频更新，近距离活动个体按需高频模拟，远处做聚合或时间推进。相机视距影响表现预算，不影响资源是否存在。

首轮可设置有限的资源区域、活动鱼群和持久化变更数量；具体上限通过现有地图与 GPU 实测确定。修改记录合并，历史日志有容量管理，随机种子和恢复状态稳定。不要把无限扩大的全海域逐鱼模拟当成真实性的必要条件。

## 17. 分阶段交付与依赖

### 阶段 0：可重复的测试场景与基线

产出：已有小鱼、中型鲹类、大海鲢三类固定种子场景；记录现有等待、遛鱼时间、张力和失败原因。大鱼测试不显示快捷键，不污染正式存档。

明确核心输入原型、受力单位与首版目标。先保留短时间对局方便验证，尚不发布小时级较量。

退出条件：能用同种子和装备复现同一局；持续收线、完全松手、合理操作都有基线记录。

### 阶段 1：先证明遛鱼好玩

范围：功能 D/E/F 的最小闭环，补装备基本受力参数；一条活动线，使用已有鱼，不先做全海域生态。

产出：冲刺带线、负载限制收线、可调泄力、合理体力变化、可操作竿角与方向、临近控鱼和起鱼、清楚的失败反馈。

退出条件：大鱼不再能靠持续硬收稳定拿下；熟练操作能更可靠成功；小鱼仍轻松。试玩证明决策有差异，而非玩家只从“按住”变成“固定两秒按两秒松”。

### 阶段 2：长局可靠性，先于长局发布

范围：功能 H，接入完整暂停、检查点、恢复、一次性结算和共享页面所有权。

产出：服务异常与浏览器切换的恢复路径；失败也能保存；输入状态不被重放。先验证 10–20 分钟对局，再延长。

退出条件：实际浏览器完成中断恢复与重复请求验证后，才能将标准档的大鱼时长提高并开放长局档。数据可靠性不过关，不靠提示“请不要刷新”补救。

### 阶段 3：一个区域的找鱼—等口闭环

范围：功能 A/B/C 的最小切片。只选码头—礁缘一带，两类已有鱼，少量饵与水层。

产出：可见鱼和咬口共享资源；资源/警戒变化；真实粗略回波；短口、长等待、试探与错过；日志记录地点和策略。

退出条件：观察能改善选点，冷清点能几分钟没口，重抛不能刷大鱼。玩家可以通过换点/饵/水层获得改善。

若阶段 1 与 2 的大鱼手感仍需调试，阶段 3 保持短等待测试，避免一次测试要耗很久才有样本。

### 阶段 4：推广至现有水域并重平衡成长

范围：所有已有鱼种的行为与适配配置、其余水域、迁移、钓点日志、经济与升级。现有体型跨度大的鱼种先验证，再批量配置。

产出：小鱼收入路线、中鱼成长、大鱼纪录挑战；标准档数值和辅助选项。

退出条件：多次 30–60 分钟正常游玩能在找鱼、钓鱼和成长之间切换，没有长期必赚刷点或失败后无法继续的经济死局。

### 阶段 5：深化海钓与长线目标

范围：潮流、漂流、船上追鱼、轻量磨损、更多钓法、委托与环境观察。每次只加入一个能解释的主要变量。

退出条件：新增机制改变玩家决策，并能从反馈理解；对局长度和复杂度增加后仍能可靠恢复。

### 阶段 6：新增鲨鱼和其他鱼种

范围：功能 K 与对应资产；沿用已验证系统。

退出条件：可见鲨鱼带来可信的找鱼目标，并具有与已有鱼不同的较量体验。

### 优先级总表

| 功能 | 优先级 | 相对工作量 | 主要依赖 |
|---|---|---|---|
| 固定场景、隐藏诊断与基线 | P0 | 小 | 现有游戏与测试 |
| 刺鱼质量、收放线、泄力、能量、起鱼 | P0 | 大 | 受力单位、装备参数、权威鱼状态 |
| 核心输入、音画与 HUD | P0 | 中 | 核心遛鱼状态 |
| 暂停、检查点、跨浏览器接管、一次性结算 | P0 | 中至大 | 遭遇状态结构、存档版本 |
| 可见鱼与咬口共享资源的最小区域 | P1 | 中至大 | 资源所有者与现有游鱼表现 |
| 饵、水层、等待、试探和局部警戒 | P1 | 中 | 最小资源系统 |
| 探鱼器、日志、经济与装备成长 | P1 | 中 | 资源与稳定节奏数据 |
| 全区域迁移、潮流、船上追鱼和磨损 | P2 | 大 | 前述闭环和保存 |
| 新钓法与目标内容 | P2 | 中至大 | 已验证操作、装备、经济 |
| 新鱼种、鲨鱼资产及专属表现 | P3 | 大 | 统一资源和遛鱼模型 |

“小/中/大”用于范围比较，不是工期承诺。并非必须把前一阶段所有扩展做完，才能验证下一阶段的最小切片；长局发布与数据可靠性的依赖不可跳过。

## 18. 验证、调参与判断标准

### 18.1 玩法自动验证

| 验证对象 | 关键场景 |
|---|---|
| 受力与线量 | 冲刺时收线可能停滞/倒退；松手不等于无限松线；鱼朝玩家游会产生余线；容量用尽可失败 |
| 体力与行为 | 低压恢复；有效施压消耗；短期爆发与长期能量不同；不能挂机稳定耗尽所有鱼 |
| 方向与起鱼 | 侧压确实改变路径；障碍风险可诊断；临近强冲不自动入袋；合理疲劳状态可起鱼 |
| 刺鱼 | 早、晚、松线、适时操作；重复抽竿无刷质量收益 |
| 机会分布 | 热点/普通/冷点、正确/错误饵层、连续重抛、低帧率下的机会率 |
| 水域与表现 | 资源钓走、脱钩、放生、迁移、远近切换；目视与声呐均不凭空造鱼 |
| 持久化 | 中断、恢复、冲突、接管、重试、重复结算、格式升级、离线恢复只应用一次 |

固定种子用于复现错误，再批量采样，例如每组 1,000 次，比较时间分布、成功率和主要失败原因。统计数量是开发建议，随成本调整。

对比四种操作策略：一直收线、一直松手、固定节奏收放、根据冲刺/线量/方向调整。合理操作应在强鱼场景明显优于前三者；不能为了击败测试策略把所有小鱼也调成高难度。

### 18.2 首轮观察指标

| 指标 | 要回答的问题 |
|---|---|
| 各条件下首次试探/有效口的 P50、P90 | 长等待真实存在吗；活跃区域是否仍有反馈 |
| 不同鱼/装备/操作的成功率、P50/P90 耗时 | 挑战来自有意义的操作吗；合理升级是否有效 |
| 空等后换点、换饵、换层的效果 | 玩家能改善局面，还是只能等随机数 |
| 固定节奏与自适应操作的差距 | 是在遛鱼，还是解一个通用按键循环 |
| 每次失败的主要原因与重复错误 | 风险可读吗；是否有不公平的秒断或莫名脱钩 |
| 每小时净收入及首次升级时间 | 增加等待后成长是否仍能持续 |
| 单次长局中值得记住的变化 | 时间延长后是否仍有进展和决策 |
| 保存失败、恢复成功和重复奖励 | 长局能否放心投入 |

P50/P90 表示一半/九成样本对应的分位值，不是给玩家展示的倒计时。目标时间从第 7、11 节草案开始，根据实测调整，不能统计没过关就靠硬性计时器强行达标。

### 18.3 浏览器试玩矩阵

至少测试：码头小鱼、礁边中鱼、船上大海鲢；普通装备、匹配装备和明显偏弱装备；白天/夜间；30/60/120 FPS 或等效模拟更新；低画质与正常画质。

长局实际验证包括：释放鼠标、切标签页、打开菜单、失去焦点、刷新、关闭重开、本地服务停止与恢复、不同浏览器接管、两个页面同时打开。项目存档文件与游戏显示必须一致。

沿用已有逻辑、起鱼、项目存档与鱼线/游鱼表现测试，补真正反映新规则的断言。构建或逻辑测试通过不代表 WebGPU 动画、输入舒适度和真实浏览器保存已验收。

### 18.4 上瘾性与可玩性的试玩判断

每轮试玩记录玩家是否能回答：

1. 我为什么选这里、这层水、这个饵？
2. 没口时，我下一步准备改变什么？
3. 这条鱼刚才为什么跑远，我又是怎么拉回来的？
4. 失败后，我知道下次能改进哪一件事吗？
5. 买这个装备，会让我尝试什么此前不好做的目标？
6. 这次成功有什么值得记住，下一次又想验证什么？

如果玩家只能回答“因为概率高、数值大、等够时间”，就需要继续调整。优先让玩家自己产生“再试一次”的理由，而不是先用更多鱼种和任务填满列表。

## 19. 第一轮建议与待试玩决定

最值得先投入的是：**已有小鱼/鲹类/大海鲢的受力遛鱼原型 + 清楚反馈 + 长局保存基础 + 一个区域的目视找鱼闭环**。通过后再推广等待和经济数值，最后扩展钓法与鱼种。

默认决策：标准海钓档；短局辅助和长局档分阶段开放；当前项目存档继续共用；隐藏大鱼测试不显示提示；新鱼种暂缓。

需要在原型中比较、可以由试玩结果决定的事项：

- 竿角由普通视角带动，还是右键独立控制更舒适。
- 释放鼠标后是否默认完整暂停，以及对应设置。
- 鱼体力常驻精确条，还是用粗略状态与音画反馈。
- 第一片资源验证区域和两类可见鱼的资产复用成本。
- 标准档大鱼 8–20 分钟是否已经足够有分量；长局 20–60 分钟是否提供足够变化。

以上项目无需在写计划时阻塞；它们是开发试玩的比较项。开始实现时按阶段范围逐项推进，避免一次同时加入资源、复杂钓法、潮流和维修，导致手感问题无法定位。
